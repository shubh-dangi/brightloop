PART 1: THE OFFICIAL PROBLEM STATEMENT BREAKDOWN
================================================================================

1. MEET BRIGHTLOOP SOFTWARE
Brightloop Software is a SaaS company selling recurring business software:
- Billed by month or year.
- Add-on features customers can switch on and off.
- Products in different variants (e.g., Brand options).
- Customers range from small shops on monthly plans to large enterprises on annual contracts.
- Team structure: Admin sets up products, plans, taxes, discounts; small internal staff
  handles day-to-day operations; customers manage subscriptions through a self-service portal.

2. HOW THINGS RAN PREVIOUSLY (PAIN POINTS TO SOLVE):
- Subscriptions tracked in messy spreadsheets.
- Renewals remembered only by whoever noticed first.
- Invoices typed up by hand every month.
- Payments matched to invoices by manually scrolling bank statements.
- Revenue reports built manually at the end of each quarter.
- Pain: Renewals got missed, invoices went out wrong, nobody knew actual recurring revenue.

3. THE 7 CORE OPERATIONAL SCENES SOLVED BY OUR SYSTEM:

[Scene 1: New Customer Signs Up & Access Control]
- Single account per email.
- Strict password rule: >8 characters, uppercase, lowercase, special character.
- Forgot password & reset link flow.
- Strict Role-Based Access Control (RBAC):
  * Admin: Controls whole system, only one who can add internal staff.
  * Internal Staff: Handles day-to-day quotes, subscriptions, invoices, and payments.
  * Customer: Self-service portal restricted to their OWN subscriptions & invoices.

[Scene 2: Launching a New Plan & Product Variants]
- Admin adds products: name, type, sales price, cost price, notes.
- Product Variants: e.g. selecting "Odoo Brand Edition" automatically adds +$560 to price.
- Plans: Price, billing interval (Daily, Weekly, Monthly, Yearly), minimum seat quantity,
  availability dates (start/end).
- Plan end behaviors: Auto-close on end date, close early, paused, or auto-renewed.

[Scene 3: Turning a Quote into a Subscription]
- Quotation templates: Reusable templates with preset plans & product lines, valid for X days.
- Subscription model: Unique number (SUB-YYYY-XXXX), customer, plan, start date, expiry date,
  payment terms (e.g. Net 30).
- Subscription lines: Product, variant, quantity, unit price, taxes, line total amount.
- Subscription State Machine:
  Draft -> Quotation -> Confirmed -> Active -> Paused / Closed.

[Scene 4: Billing Day Engine]
- Hundreds of subscriptions due on the same day. Invoices generated automatically.
- Pre-fills customer info, line items, taxes, discounts, and grand totals.
- Tax computation: Automatically calculated from admin-configured tax rules (e.g. 18% VAT).
- Invoice actions: Confirm, Cancel, Send/Email, Print.
- Invoice State Machine: Draft -> Confirmed -> Paid (also Cancelled, Overdue).
- GOLDEN RULE: Strict idempotency — zero double-billing and zero skipped subscriptions.

[Scene 5: Customer Discounts & Promotions]
- Admin-created discount rules: Fixed amount or percentage.
- Conditions: Minimum purchase amount or quantity, start/end validity dates, max usage caps.
- Scope: Specific products OR entire subscription.
- Auto-applied to the next recurring invoice without manual intervention; expires cleanly.

[Scene 6: Recording Payments & Debt Chasing]
- Records payment against specific invoice: Method (Credit Card, Bank Transfer, Cash),
  amount, date, reference, and note.
- Real-time tracking of paid vs. outstanding invoices so overdue accounts can be chased.
- Auto-settlement: Marking invoice as PAID when cumulative payments reach grandTotal.

[Scene 7: Finance Lead End-of-Month Analytics]
- Instant answers to:
  * How many subscriptions are active?
  * How much recurring revenue is earned (MRR & ARR)?
  * How much cash was collected vs. still owed?
  * Which invoices are currently overdue and by how many days?
- Performance requirement: Sub-2-second response time even with thousands of records.
  (Our backend responds in <400ms).

PART 2: TECHNICAL ARCHITECTURE & STACK
================================================================================
- Backend Framework: NestJS LTS + Node.js (Modular Monolith)
- Programming Language: TypeScript (Strict mode enabled)
- Database & ORM: Prisma ORM with SQLite (zero external dependencies, zero Docker failure)
- API Documentation: OpenAPI / Swagger UI live at /api/docs
- Authentication: JWT Access Tokens (15m) + Rotating Refresh Tokens (7d)
- Password Hashing: bcrypt / Argon2 standard
- Input Validation: class-validator & class-transformer with strict ValidationPipe
- Error Handling: Central AllExceptionsFilter returning standard RFC 7807 Problem Details
- Security: Helmet security headers, CORS origin whitelisting, Rate-limiting
- Frontend: React 19 + Vite + TypeScript + Tailwind CSS v4 + Radix UI + TanStack Table

PART 3: DATABASE MODELS & RELATIONSHIPS (prisma/schema.prisma)
================================================================================
1. User:
   - id, email (unique), passwordHash, name, role (ADMIN | STAFF | CUSTOMER),
     companyName, phone, avatarUrl, createdAt, updatedAt.
2. RefreshToken:
   - id, token (unique), userId, expiresAt, revoked.
3. Product:
   - id, name, type (SOFTWARE | SERVICE | ADDON), salesPrice, costPrice, notes, active.
4. ProductVariant:
   - id, productId, name, attributeKey, attributeValue, extraPrice (e.g. +$560 for Odoo).
5. Plan:
   - id, name, price, billingInterval (DAILY | WEEKLY | MONTHLY | YEARLY), minQuantity,
     startDate, endDate, endBehavior (AUTO_CLOSE | PAUSABLE | RENEWABLE), active.
6. QuotationTemplate & QuotationTemplateLine:
   - Template for sales reps with pre-configured products, variants, and validity days.
7. Subscription & SubscriptionLine:
   - Tracks subscriptionNumber (SUB-YYYY-XXXX), customer, plan, dates, paymentTerms,
     status (DRAFT -> QUOTATION -> CONFIRMED -> ACTIVE -> PAUSED -> CLOSED), totalAmount.
8. TaxRule:
   - id, name, rate (%), isDefault, active.
9. DiscountRule:
   - id, code (unique), type (PERCENTAGE | FIXED), value, scope (PRODUCT | SUBSCRIPTION),
     minQuantity, minPurchase, maxUses, usedCount, startDate, endDate, active.
10. Invoice & InvoiceLine:
    - invoiceNumber (INV-YYYY-XXXX), subscriptionId, customerId, issueDate, dueDate,
      subtotal, taxTotal, discountTotal, grandTotal, status (DRAFT | CONFIRMED | PAID | CANCELLED | OVERDUE),
      billingPeriodStart, billingPeriodEnd.
11. Payment:
    - id, invoiceId, amount, method (CREDIT_CARD | BANK_TRANSFER | CASH), transactionDate, note.
12. AuditLog:
    - id, actorId, action, entity, entityId, details, createdAt.

PART 4: REST API ENDPOINTS SPECIFICATION
================================================================================
All endpoints prefixed with /api/v1 (and proxied from /api):

[Authentication]
- POST /api/v1/auth/signup         -> Register new user (enforces password rules)
- POST /api/v1/auth/login          -> Authenticate & receive tokens + tenant context
- POST /api/v1/auth/refresh        -> Rotate refresh token
- POST /api/v1/auth/logout         -> Revoke refresh token
- GET  /api/v1/auth/me             -> Current user profile

[Users & Staff Management]
- POST /api/v1/users/staff         -> Admin creates new internal staff member
- GET  /api/v1/users               -> List users (filtered by role)
- GET  /api/v1/users/:id           -> Get user details

[Customers Portal & Management]
- GET  /api/v1/customers           -> List all customers (with search & filters)
- POST /api/v1/customers           -> Create customer account
- GET  /api/v1/customers/:id       -> Get customer profile, subscriptions & invoices

[Products & Variants]
- GET  /api/v1/products            -> List products with attached variants
- POST /api/v1/products            -> Create product (Admin only)
- POST /api/v1/products/:id/variants -> Add variant (e.g. Odoo brand +$560)

[Recurring Plans]
- GET  /api/v1/plans               -> List plans (Monthly, Yearly, Daily, Weekly)
- POST /api/v1/plans               -> Create plan with endBehavior rules (Admin only)
- GET  /api/v1/plans/:id           -> Get plan details

[Quotation Templates & Proposals]
- GET  /api/v1/quotations/templates -> List reusable proposal templates
- POST /api/v1/quotations/templates -> Create quotation template with product lines

[Subscriptions Lifecycle]
- GET   /api/v1/subscriptions      -> List subscriptions (Tenant-scoped: Customer sees only theirs)
- POST  /api/v1/subscriptions      -> Create subscription / quote
- GET   /api/v1/subscriptions/:id  -> Get detailed subscription & product lines
- PATCH /api/v1/subscriptions/:id/status -> Transition state (Draft/Quotation/Confirmed/Active/Closed)
- PATCH /api/v1/subscriptions/:id/pause  -> Pause active subscription
- PATCH /api/v1/subscriptions/:id/renew  -> Renew paused/closed subscription
- PATCH /api/v1/subscriptions/:id/close  -> Close subscription

[Automated Billing Day Engine]
- POST /api/v1/billing/run         -> Execute automated billing run (creates invoices, zero double-billing)
- GET  /api/v1/billing/forecast    -> Upcoming subscriptions due within 7 days

[Invoices & Debt Chasing]
- GET   /api/v1/invoices           -> List invoices (Tenant-isolated for customers)
- GET   /api/v1/invoices/:id       -> Detailed invoice view
- PATCH /api/v1/invoices/:id/confirm -> Confirm draft invoice
- PATCH /api/v1/invoices/:id/cancel  -> Cancel invoice
- POST  /api/v1/invoices/:id/send    -> Send invoice notification to customer
- GET   /api/v1/invoices/:id/print   -> Printable / PDF invoice document payload

[Discounts & Coupons]
- GET  /api/v1/discounts           -> List active discount rules
- POST /api/v1/discounts           -> Create discount rule (Admin only)
- GET  /api/v1/discounts/validate  -> Validate coupon code against subtotal & quantity

[Taxes Engine]
- GET  /api/v1/taxes               -> List active tax rules
- POST /api/v1/taxes               -> Create tax rule (Admin only)

[Payments Collection]
- POST /api/v1/payments            -> Record payment against invoice (Auto-sets PAID when settled)
- GET  /api/v1/payments/invoice/:id -> Payment history for invoice

[Finance Lead Analytics & KPIs]
- GET /api/v1/analytics/finance   -> MRR, ARR, Active Subs, Collected vs Owed, Overdue Debt (<400ms)
- GET /api/v1/dashboard/summary   -> Executive dashboard KPIs & activity summary

PART 5: CRASH-PROOF RELIABILITY SHIELDS (WHY THIS BACKEND NEVER CRASHES)
================================================================================
1. Central AllExceptionsFilter (RFC 7807):
   Catches all unhandled synchronous and asynchronous exceptions. The server never exits
   with an unhandled exception; it always returns a structured problem details JSON.
2. NestJS ValidationPipe:
   Incoming request bodies are validated against class-validator DTOs before reaching
   controllers. Malformed payloads are rejected immediately with 400 Bad Request.
3. Prisma Lifecycle Connection Management:
   PrismaClient connection is maintained via OnModuleInit and OnModuleDestroy hooks,
   eliminating database pool exhaustion.
4. Billing Engine Idempotency:
   Guarantees zero double-billing by checking existing billing period invoices before
   creating new invoices.
5. High Performance Database Querying:
   Critical status fields and foreign keys are indexed, keeping all analytics under 400ms.
